按你现在的代码实现，我把新算法拆成几层讲，再和论文逐点对比。

**宏观流程：每次运行都从“当前上传的数据”出发**

1. 读取当前附件 2/3，计算钢板特征、切割工时、资源数量。
2. 用当前数据跑一次 FIFO，得到 FIFO 基线：Cmax、齐套跨度、负载差、总等待时间、理论下界 LB。
3. 生成初始种群：个体是“钢板顺序 OS + 每张钢板的切割机分配 MS”。
4. 对每个个体跑完整离散事件仿真，得到指标向量。
5. NSGA-II 做非支配排序、交叉、变异、概率精英保留。
6. 保留 Pareto 前沿。
7. 从同一个前沿分别选出“重工时”和“兼顾三指标”两个交付解。

关键点：LB 和 FIFO 基线不是固定常量，而是随当前数据重新计算的。所以公司换一批钢板后，算法不会使用旧的绝对目标，而是自动按新数据重新缩放。

**个体编码：为什么不是原来的单纯钢板顺序**

论文里的 MO-FJSP 同时要决策“工序顺序”和“机器选择”。你们原来的模型只优化钢板顺序，N2/N5 是由仿真内部的 `pick_machine()` 自动决定。

现在 DQN+NSGA-II 把 N2/N5/N8 分配显式写成机器码：

```text
个体 = 钢板顺序 [A1, A2, B1, ...]
     + 每张钢板对应的机器 [N2, N5, N2, ...]
```

评估时仿真不再用 `pick_machine()` 覆盖机器码，而是按照机器码生成切割排程，再继续仿真下游打磨、坡口、AGV、缓存和齐套。这样 NSGA-II 才真正在“顺序 + 机器”两层决策上搜索。

**DQN 的 `.pt` 文件到底存什么**

`dqn_machine_model.pt` 不是存排产表，也不是存已经算好的钢板结果，它只存一个小神经网络的权重：

```text
输入: 16 维特征
隐藏: 128 -> 64
输出: 5 个动作，固定对应 N2/N5/N8/N9/N10
```

输入特征不包含钢板名称，也不包含附件文件名，只包括：

```text
钢板厚度
钢板宽度
当前钢板切割工时
齐套优先级
当前机器负载
机器负载向量
剩余总任务量
```

模型会额外保存一个 `.meta.json`，记录训练时见过的钢板数范围、厚度范围、宽度范围、切割工时范围。作用是防止对完全不同的新数据强行使用旧模型。

**有 `.pt` 文件时的运行逻辑**

如果 `dqn_machine_model.pt` 存在、torch 可用、且当前数据特征范围与 `.meta.json` 匹配，则 DQN 参与生成少量初始机器码。

生成方式是：对某个钢板顺序，逐张钢板询问 DQN。DQN 看到当前机器负载和这张钢板的物理特征，输出各台机器的 Q 值，再从 N5 厚度/宽度约束允许的机器里选 Q 值最大的机器。

但 DQN 不会占据整个种群。默认只允许它产生大约种群 20% 的个体，其余 80% 仍由 FIFO、齐套优先、分段短工时、天车感知等启发式机器码组成。`dqn_seed_count` 可以设为 0，设 0 时完全不使用 DQN。

**没有 `.pt` 文件或特征不匹配时的逻辑**

没有模型文件、torch 未安装、模型缺少 `.meta.json`、或者当前钢板数与训练范围差异过大时，DQN 部分被跳过，代码会打印一条提示，然后退回到纯启发式机器码。

这时算法实际变成“启发式种子 + 多目标 NSGA-II”：

- 钢板顺序仍来自 FIFO、齐套优先、分段短工时、天车感知等；
- 机器码来自负载均衡、N2 偏好、N5 偏好和随机扰动等确定性策略；
- NSGA-II 继续在当前数据上搜索；
- 最终结果结构和 DQN 存在时完全相同。

所以模型文件缺失不会报错，也不会导致结果不可用。这也是你们只有一份真实附件时最安全的运行方式。

**NSGA-II 主循环在做什么**

初始种群生成后，每个个体都要跑一次完整仿真，得到四个目标：

```text
f1 = Cmax / LB            产能效率
f2 = 齐套跨度相对FIFO      齐套
f3 = 切割负载差相对FIFO    负载均衡
f4 = 总等待时间相对FIFO    等待软指标
```

NSGA-II 对这四个目标做非支配排序：

```text
解A支配解B:
A 的所有目标都不比 B 差
且至少一个目标严格比 B 好
```

排序后计算拥挤度，选择时使用锦标赛选择。交叉时对钢板顺序用 OX 排列交叉，机器码按个体交叉；变异时既修改钢板顺序，也修改某张钢板的机器分配。

精英保留采用类似论文的概率保留：前面非支配层保留概率高，随着代数增加会保留一部分低层个体，避免种群很快挤到同一个区域。最终从所有历史评估结果中提取非支配前沿。

**原论文的实现逻辑**

原论文解决的是标准 MO-FJSP，目标主要是：

```text
最小化最大完工时间 makespan
最小化能耗
```

论文把 DQN 当作“初始解生成器”。它的思路是：

1. 先随机或启发式生成一批工序顺序 OS；
2. 固定 OS，DQN 逐工序选择机器 MS；
3. DQN 状态包括当前全局机器空闲状态和当前工序在各机器上的加工时间/能耗；
4. 动作是选择某台机器；
5. 奖励结合局部影响和全局影响，并用 PCA 把两个目标压缩成一个奖励值；
6. 训练前期更重视局部奖励，后期更重视全局奖励；
7. 用训练好的 DQN 批量生成高质量 OS/MS 初始解；
8. 把这些初始解放进改进 NSGA-II，由 NSGA-II 做后续 Pareto 进化；
9. NSGA-II 的概率精英保留避免第一前沿垄断种群。

论文侧重点是“证明 DQN 初始解能明显优于贪婪初始解”，所以实验会对比 DQN 种子、贪婪种子、随机种子在 MK 标准算例上的收敛速度、覆盖度、稳定性。

**两者对比**

| 维度 | 原论文 | 你们当前实现 |
|---|---|---|
| 问题 | 标准 MO-FJSP | 船体钢板排序 + N2/N5/N8 + 齐套配盘 |
| 决策 | OS + MS | 钢板顺序 + 显式机器码 |
| DQN 作用 | 必需的高质量初始解生成器 | 可选的少量辅助种子 |
| 没有 DQN | 不成立 | 仍可纯启发式 + NSGA-II |
| 目标 | makespan、能耗 | Cmax/LB、齐套、负载、等待 |
| 奖励 | 局部 + 全局，PCA 压缩 | 简化版局部负载奖励 + 终局仿真奖励 |
| NSGA-II | 标准非支配 + 概率精英 | 非支配 + 拥挤度 + 概率精英 |
| 输出 | Pareto 前沿 | 同一 Pareto 前沿再选重工时/兼顾三指标 |
| 数据 | MK 系列等多算例 | 当前只有一份真实附件 |
| 风险 | 依赖训练数据分布 | 已加元数据范围检查，异常时自动退回 |

**对二者侧重点的总结**

原论文更偏“算法研究”：它认为 FJSP 的难点在于机器选择组合空间大，随机 NSGA-II 初始种群太差，所以用 DQN 学会更好的初始机器分配，再用 NSGA-II 保持全局搜索。

你们现在的实现更偏“交付稳定性”：公司未来会有不同钢板，但当前只有一份附件。因此我把 NSGA-II 做成真正的主搜索器，DQN 只做可插拔种子；即使 DQN 对未知数据失效，也不会让整套系统失效。简单说，论文把 DQN 当成“必须用的起跑器”，你们这套实现把 DQN 当成“可用可不用、用之前还要检查跑道是否合适的辅助工具”。
