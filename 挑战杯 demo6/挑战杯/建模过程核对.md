> 适用版本：`挑战杯 demo6/挑战杯` 工程

## 2. 数据校验与判断标准

代码入口：`load_and_validate()`，位于 `steel_schedule_model.py`。

### 2.1 表与字段校验

- 钢板表必须包含：`分段号`、`套料图名`、`零件总数`、`穿孔数`、`切割长度(mm)`、`空行程长度(mm)`、`划线长度(mm)`、`V坡长度(mm)`、`小件数量`、`大件数量`。
- 零件表必须包含：`零件名`、`套料图名`、`零件类型`、`切割长度(mm)`、`V坡长度(mm)`、`Y坡长度(mm)`、`K坡长度(mm)`、`I坡长度(mm)`、`X坡长度(mm)`、`齐套优先级`、`打磨长度(mm)`。
- `套料图名`、`零件名` 不允许重复。
- 零件表中的 `套料图名` 必须能在钢板表中找到。

### 2.2 零件类型映射

`零件类型` 统一转为小写：

```text
小件 -> small
大件 -> large
small -> small
large -> large
```

非上述类型会被判为数据错误。

### 2.3 数据一致性检查

| 检查项 | 判断标准 |
|---|---|
| 未匹配零件数 | 零件合并到钢板后 `分段号` 为空的数量应为 0 |
| 零件数不一致钢板数 | 钢板 `零件总数` 与零件明细数不一致的钢板数应为 0 |
| 小件数不一致钢板数 | 钢板 `小件数量` 与明细小件数不一致的钢板数应为 0 |
| 大件数不一致钢板数 | 钢板 `大件数量` 与明细大件数不一致的钢板数应为 0 |
| V坡长度不一致钢板数 | 钢板 `V坡长度` 与零件 `V坡长度` 合计差异超过 0.01mm 的钢板数应为 0 |
| 打磨长度缺失零件数 | 记录缺失清单；仿真中缺失值按 0 处理 |

### 2.4 N5 设备资格判断

`pick_machine()` 在排程时使用：

```text
N5 可用条件：
  钢板厚度 <= 36mm
  且（钢板宽度未知，或宽度 <= 4500mm）
```

不满足条件时只能分配 N2；N2 始终可作为后备机台。

### 3.2 附件3速度表

`load_process_params()` 从附件3读取：

```text
厚度(mm), 直切速度(mm/min), V&Y坡切速度(mm/min), X&K坡速度(mm/min)
```

查表规则 `_get_speeds_for_thickness()`：

- 厚度精确命中速度表时，直接使用该行速度。
- 厚度落在两个已知厚度之间时，对三种速度分别做线性插值。
- 厚度小于表内最小厚度时，使用最小厚度速度。
- 厚度大于表内最大厚度时，使用最大厚度速度。

### 3.3 自适应资源配置公式

`ModelConfig.adapt_to_data()` 会根据数据规模与工艺负荷调整下游设备数量，判断标准如下：

```text
data_scale_factor = clamp(n_plates / 109, 0.35, 2.5)
target_minutes = 67.25 * 60 * 0.75 * data_scale_factor
```

自动坡口台数：

```text
小件坡口零件数 = 零件类型为 small 且 Y/X/K 坡合计 > 0 的零件数
overhead_time = 小件坡口零件数 * 3.5
total_bevel = sum(Y坡长度) + sum(X坡长度) + sum(K坡长度)
variable_time = total_bevel * (小件数 / 总零件数) / auto_bevel_speed
auto_bevel_min = overhead_time + variable_time
need = floor(auto_bevel_min / target_minutes)
auto_bevel_machines = clamp(need + (1 if auto_bevel_min > target_minutes * 0.5 else 0), 1, 4)
```

人工坡口工位数：

```text
manual_bevel_min = total_bevel * (大件数 / 总零件数) / manual_bevel_speed
need = floor(manual_bevel_min / target_minutes)
manual_bevel_stations = clamp(need + (1 if manual_bevel_min > target_minutes * 0.4 else 0), 1, 6)
```

大件打磨设备数：

```text
total_grind = sum(打磨长度)
large_grind_min = total_grind * (大件数 / 总零件数) / large_grind_speed
need = floor(large_grind_min / target_minutes)
large_grinders = clamp(need + (1 if large_grind_min > target_minutes * 0.5 else 0), 2, 8)
```

## 4. 每道工序的时间公式

### 4.1 钢板切割时间

默认使用分项明细公式，代码入口：`cut_duration()`。

对每张钢板：

```text
t_straight = L_cut / v_straight
t_vy       = L_V / v_vy
t_empty    = L_空行程 / v_rapid
t_mark     = L_划线 / v_mark
t_pierce   = N_穿孔 * 0.1
t_setup    = 3
T_cut      = t_straight + t_vy + t_empty + t_mark + t_pierce + t_setup
```

其中：

| 符号 | 含义 |
|---|---|
| `L_cut` | 钢板 `切割长度(mm)` |
| `L_V` | 钢板 `V坡长度(mm)` |
| `L_空行程` | 钢板 `空行程长度(mm)` |
| `L_划线` | 钢板 `划线长度(mm)` |
| `N_穿孔` | 钢板 `穿孔数` |
| `v_straight` | 按厚度查附件3的直切速度 |
| `v_vy` | 按厚度查附件3的 V&Y 坡切速度 |
| `v_rapid` | 空行程速度，默认 24000 mm/min，即 24m/min |
| `v_mark` | 划线速度，默认 24000 mm/min，即 24m/min |

`physical_limit_analysis.py` 对 109 张钢板逐张重算并和 `cut_duration()` 对比，最大误差为 0。

### 4.2 小件路径时间

小件路径：

```text
切割完成 -> 桁架分拣 -> 自动打磨 -> （需要坡口则自动坡口） -> 桁架码垛
-> 机旁码垛 -> AGV到半框/坡口 -> 半框缓存 -> 齐套
```

#### 4.2.1 桁架分拣

```text
若 打磨长度 > 0：
    t_sort = 1.58 min/件
否则：
    t_sort = 1.00 min/件（切割台直接码垛）
```

桁架有两个臂；同一臂从 N2 切到 N5 或反向切换时，增加 `0.5 min` 移动时间。

#### 4.2.2 自动打磨

```text
t_sg = 2 * L_grind / v_sg + 1.0
```

其中：

- `L_grind`：零件 `打磨长度(mm)`，缺失按 0
- `v_sg`：`2520 mm/min`
- `1.0`：视觉扫描时间

#### 4.2.3 自动坡口

是否进入自动坡口，当前代码判断为：

```text
自动坡口长度 > 0
```

当前 `load_and_validate()` 已将 `自动坡口长度` 设置为 `Y坡 + X坡 + K坡`，因此只对真实 Y/X/K 坡零件触发。

时间公式：

```text
t_ab = Y / v_vy + (X + K) / v_xk + 3.5
```

其中：

- `Y/X/K`：对应坡口长度
- `v_vy`：按厚度查附件3的 V&Y 坡切速度
- `v_xk`：按厚度查附件3的 X&K 坡切速度
- `3.5`：扫描 2min + 预热 0.5min + 翻面 1min

#### 4.2.4 桁架码垛

```text
t_palletize = 1.17 min/件
```

### 4.3 大件路径时间

大件路径：

```text
切割完成 -> 切割胎架自由边打磨 -> 天车吊运
-> （需要坡口则人工坡口） -> 成品放置区
```

#### 4.3.1 切割胎架自由边打磨

大件在切割完成后，直接在刚才的切割胎架上进行自由边打磨：

```text
t_lg = L_grind / 1950
```

#### 4.3.2 天车吊运

```text
t_crane_large = 5 min/件
```

#### 4.3.3 人工坡口

```text
t_mb = L_manual_bevel / 250
```

其中 `L_manual_bevel` 的口径是关键：

- 当前代码：`L_manual_bevel = Y坡 + X坡 + K坡`，V 坡在切割机完成，I 坡不计入人工坡口。

数据 `data_0` 下两种口径差异：

| 口径 | 大件人工坡口总负荷 | 单工位理论下限 |
|---|---:|---:|
| 旧口径 `坡口总长` | 4961.05 min | 82.68 h |
| 当前代码 `Y+X+K` | 943.20 min | 15.72 h |

### 4.4 天车、桁架、AGV 资源占用规则

#### 4.4.1 ResourcePool

普通设备资源池：

```text
start = max(ready_time, min(free_time of all resources))
end   = start + duration
```

#### 4.4.2 TrussPool

```text
若桁架臂上次服务机台与本次不同：
    effective_ready = max(ready, free_time + 0.5)
否则：
    effective_ready = max(ready, free_time)
```

#### 4.4.3 AGVPathNetwork

AGV 区域模型：

```text
区域：N2区、N5区、加工区、齐套区
跨区移动惩罚：0.5 min
候选AGV就绪时间 = max(任务就绪时间, AGV空闲时间 + 跨区惩罚, 起点区域释放时间)
```

路径冲突等待：

```text
若 目标区域释放时间 > 候选开始时间 + 运输时长 * 0.5：
    开始时间延迟到目标区域释放时间
```

区域占用更新：

```text
起点区域释放时间 = max(原值, start + duration * 0.5)
终点区域释放时间 = max(原值, end)
```

#### 4.4.4 天车预留

```text
start = max(任务就绪时间, 天车空闲时间, 所在区域释放时间, 同区域AGV占用时间)
```

### 4.5 料框与 AGV 转运

料框分组规则：

```text
料框 = (分段号, 齐套优先级, 是否坡口件, 零件类型)
```

小件料框 AGV 移动次数：

| 料框类型 | 移动次数 | 单次时间 |
|---|---:|---:|
| 非坡口小件料框 | 1 次到半框 | 2.75 min |
| 坡口小件料框 | 2 次：到坡口 + 到半框 | 2.75 min/次 |
| 齐套后小件料框 | 1 次到齐套缓存 | 2.75 min |

大件不通过 AGV，使用天车吊运。

## 5. 仿真流程与事件口径

### 5.1 切割排程构造

后端模型使用的排程构造逻辑：

```text
按给定钢板顺序逐张分配：
    机台 = 最早空闲且满足 N5 资格约束的切割机
    切割开始 = 机台空闲时间
    切割结束 = 切割开始 + T_cut
    机台空闲时间 = 切割结束
```

双工位切割机下，当前工位释放后另一工位可直接开始下一张板；不再把每板 5min 天车串行进切割排程。

### 5.2 Phase 1：零件加工

仿真入口 `simulate()`。

按 `切割完成时间、齐套优先级、零件名` 排序后逐零件处理：

- 小件依次经过：桁架分拣 -> 自动打磨 -> （自动坡口） -> 桁架码垛。
- 大件依次经过：切割胎架自由边打磨 -> 天车吊运 -> （人工坡口）。

每个工序都写入 `process_stages`：

```text
零件名, 工序, 资源, 开始(min), 结束(min), 时长(min)
```

### 5.3 Phase 2：料框、缓存与齐套门控

缓存容量：

| 缓存 | 容量 |
|---|---:|
| N2 码垛 | 10 框 |
| N5 码垛 | 18 框 |
| 坡口缓存 | 3 框 |
| 半框缓存 | 30 框 |
| 齐套缓存 | 15 框 |

料框进入缓存时，缓存占用按“框”计数，不是按零件数。

齐套规则：

```text
同一 (分段号, 齐套优先级) 的全部零件都到达半框缓存/成品区后，
该组的小件料框才允许由 AGV 转运到齐套缓存区。
```

已齐套料框在齐套缓存区停留 `60 min`。

### 5.4 当前仿真实现问题

当前 `simulate()` 的齐套门控存在实现 bug：

```text
group_total 按零件数计数；
group_arrived 每次按“一个料框”累加 1。
```

因此多件料框的齐套组几乎永远无法触发“全部零件已到齐”的判断，`AGV转齐套缓存` 不会发生。
当前 `physical_limit_analysis.py` 的场景对照中，5 个场景的 `AGV转齐套缓存次数` 均为 0。

这会导致：

- `到齐套区(min)` 混用了未更新的初始值；
- `总完工时间(h)`、`整体产能(张板/班)` 与真实齐套完成时间不一致；
- 齐套跨度计算使用的是“到半框缓存”，仍可核对，但不能替代最终齐套时间。

### 5.5 齐套建模流程与逐段转运条件

#### 5.5.1 整体齐套链路

```text
切割完成
  -> 小件：桁架分拣 -> 自动打磨 -> (自动坡口) -> 桁架码垛
  -> 大件：切割胎架自由边打磨 -> 天车吊运 -> (人工坡口) -> 成品放置区

小件按料框进入 Phase 2：
机旁码垛 -> AGV至坡口/半框 -> (坡口缓存) -> 半框缓存
        -> 同组全部零件就绪 -> AGV至齐套缓存 -> 停留60min
```

大件不进入料框和 AGV 转运，加工完成后直接视为“已到达半框/成品区”，参与组齐套判断。

#### 5.5.2 料框定义

```text
料框 key = (分段号, 齐套优先级, 是否坡口件, 零件类型)
```

小件按此 key 聚合成料框；大件虽然也进入 `bin_parts` 字典，但在事件初始化时被跳过。

当前代码中“是否坡口件”的判断：

- 小件：`自动坡口长度(mm) > 0`
- 大件：`人工坡口长度(mm) > 0`

当前 `load_and_validate()` 已将这两个字段统一设置为 `Y坡 + X坡 + K坡`，不再包含 V 坡和 I 坡。

#### 5.5.3 机旁码垛到坡口/半框的转运条件

事件类型 `kind=0`：

```text
bin_ready = max(该料框内所有零件的桁架码垛完成时间)
```

转运到半框/坡口前需满足：

| 条件 | 判断标准 |
|---|---|
| 料框已齐 | 该料框内所有零件都已完成 Phase 1 的 `桁架码垛` |
| 机旁码垛容量 | 对应切割机码垛区占用框数 < N2=10 / N5=18 |
| AGV 可用 | AGV 路径网络返回可用时间 |
| 坡口缓存容量 | 若为坡口料框，`AGV到达后坡口缓存占用 < 3`，否则等待 |

非坡口料框：

```text
AGV 1 次，2.75 min：
机旁码垛 -> 半框缓存
```

坡口料框：

```text
AGV 第 1 次，2.75 min：
机旁码垛 -> 坡口缓存

坡口缓存停留时间：
bevel_end = AGV到达时间 + sum(该料框内零件 Phase 1 自动坡口时长)

AGV 第 2 次，2.75 min：
坡口缓存 -> 半框缓存
```

注意：自动坡口设备加工已经在 Phase 1 按零件完成；Phase 2 的“坡口缓存停留”只是把料框内自动坡口时长合计作为缓存占用时间，并不再次占用自动坡口设备。

#### 5.5.4 半框到齐套的转运条件

事件类型 `kind=1`：

设计意图：

```text
同一 (分段号, 齐套优先级) 组内所有零件都已到达半框缓存/成品区后，
该组所有小件料框才从半框缓存转运到齐套缓存。
```

代码初始化：

```text
group_total = 该组零件总数
group_arrived = 该组大件数
group_last_ready = max(该组大件加工完成时间)
```

每个小件料框到达半框后：

```text
group_arrived += 1
group_last_ready = max(group_last_ready, 该料框到半框时间)
```

当 `group_arrived >= group_total` 时，触发该组所有小件料框的 `kind=1` 事件。

#### 5.5.5 当前实现 bug

```text
group_total 是零件数；
group_arrived 按料框数累加。
```

因此只有“一个料框对应一个零件”的组才能满足判断；多件料框的组不会触发 `AGV转齐套缓存`。

`data_0` 修正坡口口径下，固定小件料框数为 33：

- 非坡口料框：21
- 坡口料框：12

实际场景对照中，33 个料框都能到达半框，但 `AGV转齐套缓存次数 = 0`。

#### 5.5.6 齐套缓存停留

```text
AGV到达齐套缓存后：
齐套缓存占用事件 = [AGV结束时间, AGV结束时间 + 60min]
```

当前代码在 `kind=1` 前不检查半框缓存容量和齐套缓存容量，只在该次转运结束后记录缓存事件；如果峰值超过容量，会在指标中产生溢出警告。

#### 5.5.7 零件完成时间口径

```text
大件：
到半框缓存 = 加工完成时间
到齐套区   = 加工完成时间（大件直接到成品区）

小件：
到半框缓存 = 料框完成坡口/AGV转运后到达半框的时间
到齐套区   = kind=1 事件中 AGV 到达齐套缓存的时间
```

由于 `kind=1` 不触发，当前小件 `到齐套区` 实际上仍停留在 Phase 1 的初始值，不能作为最终齐套时间。

## 6. KPI 计算公式与判断标准

### 6.1 总完工时间

```text
总完工时间(h) = max(零件“到齐套区(min)”) / 60
```

当前实现因第 5.4 节 bug，建议把 `到半框缓存` 和真实齐套事件一起核对。

### 6.2 齐套跨度

```text
齐套跨度(min) = 组内最后一件到达半框缓存的时间 - 组内第一件到达半框缓存的时间
加权平均齐套跨度(h) = sum(组零件数 * 组跨度) / 总零件数 / 60
```

### 6.3 切割负载差

```text
切割负载差(h) = (最重切割机总切割工时 - 最轻切割机总切割工时) / 60
```

### 6.4 整体产能

```text
整体产能(张板/班) = 钢板数 / (总完工时间(h)) * 8
```

### 6.5 切割机稼动率

综合稼动率：

```text
综合稼动率 = 总切割工时 / (切割机数量 * 总完工时间)
```

纯切割稼动率：

```text
纯切割工时 = 每机总切割工时 - 该机钢板数 * 每张固定开销
纯切割稼动率 = 纯切割工时 / (切割机数量 * 总完工时间)
```

班次稼动率：

```text
班次数 = ceil(总完工时间 / 8h)
班次稼动率 = 总切割工时 / (切割机数量 * 班次数 * 8h * 60min)
```

### 6.6 资源利用率

```text
某资源利用率 = 该资源所有工序总时长 / 所有工序最大结束时间
```

### 6.7 竞赛/公司参考指标

| 指标 | 参考值 |
|---|---:|
| 整体产能 | 13 张板/班（8h/班） |
| 总完工时间 | 67.25 h |
| 切割机稼动率 | 61% |
| 流向平均齐套时长 | 12.7 h |
| 代码中负载差目标 | 1.0 h |

## 8. 需要重点核对/修正的口径

### 8.1 人工坡口长度

- 当前代码：`人工坡口长度 = Y坡 + X坡 + K坡`。
- 依据：V 坡在切割机完成；项目文档/代码注释均写明 I 坡不计入人工坡口。
- `data_0` 下人工坡口总负荷约 943.20 min，单工位理论下限约 15.72h。

### 8.2 自动坡口触发条件

- 当前代码：`自动坡口长度 = Y坡 + X坡 + K坡`，只有 `Y+X+K > 0` 才进入自动坡口。
- `data_0` 下自动坡口总负荷约 424.15 min，单工位理论下限约 7.07h。

### 8.3 双工位残材并行

- 当前模型：`cut_remainder_minutes = 0`，残材断料/换料由双工位另一工位并行处理。
- 切割时间只计直切、V坡、空行程、划线、穿孔、换板准备。
- 若需要回退旧口径，可将 `cut_remainder_minutes` 临时调回 25。

### 8.4 天车口径

- CLI、`improved_optimizer.schedule_from_order()`、后端动态重排均已去掉每板 5min 天车串行。
- 天车只用于大件切割胎架打磨后的吊运，时间为 5min/件。

### 8.5 齐套门控事件

`simulate()` 中 `group_arrived` 应按“零件数”累加，或把 `group_total` 改为“料框数”，否则最终齐套转运不会触发。

### 8.6 大件桁架预留

已移除大件占用桁架 `0.948 min/件` 的逻辑；大件切割完成后直接在切割胎架进行自由边打磨。

### 8.7 0.8/0.6 打包系数

新模型默认使用分项明细公式，空行程、划线、穿孔、换板均显式计算，不再使用附件3公式中的 `÷0.8÷0.6` 打包系数。
`use_component_formula=0` 时仍保留附件3官方公式作为可切换口径。
若公司口径要求保留该系数，需要重新确认空行程/划线是否仍显式计入，避免重复计算。
