# 船体加工车间智能排产与齐套配盘系统用户手册

## 1. 手册用途

本手册用于运行和复现“船体加工车间智能排产与齐套配盘优化调度”作品，包含以下内容：

- Web 端启动和操作；
- 附件 2、附件 3 的导入方式；
- DQN+NSGA-II、GA+LNS、SA+Tabu 等算法的选择；
- 设备故障、订单取消、优先级变更和在制钢板处置；
- 结果文件、图表和 KPI 的解释；
- 命令行复现、环境要求和常见问题。

项目中的算法代码和仿真测试程序位于当前工程根目录，完整技术报告位于：

`提交材料/船体加工车间智能排产与齐套配盘优化调度技术方案报告.docx`

### 2.3 仿真实验矩阵

| 实验类型 | 改变因素 | 固定条件 | 主要观察 |
|---|---|---|---|
| FIFO 基线 | 使用原始钢板顺序 | 数据、设备、评价函数 | 建立比较基准 |
| 主方案搜索 | DQN+NSGA-II、固定种子 | 附件 2、附件 3、资源数量 | Pareto 前沿和综合交付解 |
| 算法对照 | SA+Tabu、GA+LNS、DQN+NSGA-II | 数据、预算、KPI | 算法适用性和输出形态 |
| 评价函数对照 | 线性、二次、Pareto、动态目标 | 数据、资源和约束 | 多目标权衡 |
| 故障响应 | 资源、开始时间、持续时间 | 基础排程和订单 | 响应时间、冻结/重排数量 |
| 订单变更 | 取消、优先级、替换数据 | 故障清单和资源 | 在制处置和齐套恢复 |
| 缓存压力 | 缓存和坡口站容量 | 钢板顺序和资源 | 峰值占用和溢出告警 |

同一组对照必须使用相同输入数据和相同 KPI 口径。不要把不同月份、不同设备数量或不同缓存参数下的结果直接放在同一张表中比较。

### 2.4 多进程并行加速

候选解之间相互独立，系统按算法类型使用多进程评估：

| 算法 | 并行对象 | 加速方式 |
|---|---|---|
| DQN+NSGA-II | 种群中的每个个体 | 主进程执行非支配排序和遗传操作，进程池并行运行完整仿真 |
| GA+LNS | 每代子代个体 | 进程池并行评估，父进程统一选择、存档和输出 |
| SA+Tabu | 每个初始策略 | 不同初始解分配不同 worker，通过队列回报进度 |
| 二次 SA | 多初始策略 | 使用同一并行框架 |
| DRL-guided SA | 多初始策略 | 各 worker 独立更新代理，父进程汇总结果 |
| 静态双轨 | 产能优先与三指标平衡 | 两条轨道分半使用 CPU |

控制方式：

```text
parallel_workers=1
```

或在环境变量中设置：

```text
OPTIMIZER_PARALLEL=0
```

串行模式便于严格复现。默认并行模式使用 `spawn`（Windows）或 `fork`（类 Unix），普通算法两条交付轨道合计使用全部核心，DQN+NSGA-II 因只运行一次 Pareto 搜索而直接使用全部核心。

## 4. 数据准备

### 4.1 必选文件

附件 2：钢板零件数据，工作表必须包含：

- 钢板数据表；
- 零件数据表；
- 分段号、套料图名、零件名；
- 切割长度、V 坡长度、厚度、宽度；
- 小件数量、大件数量、齐套优先级；
- 打磨长度、Y/X/K/I 坡长度。

### 4.2 可选文件

附件 3：工艺用时计算表，用于提供厚度相关速度表：

- 直切速度；
- V&Y 坡切速度；
- X&K 坡切速度。

厚度未精确命中时，程序在相邻厚度之间做线性插值；低于最小厚度或高于最大厚度时使用边界速度。

### 4.3 数据校验

系统会检查：

- 零件是否能关联到钢板；
- 钢板零件总数、小件数、大件数是否与零件明细一致；
- V 坡长度汇总是否一致；
- 是否存在重复套料图名或重复零件名；
- 是否存在缺失的打磨长度。

任何影响可行性的校验失败都会阻止正式计算，并返回错误信息。缺失打磨长度会保留原值，仿真中按要求处理，并在结果摘要中列出。

### 5.3 选择算法

项目实现了多种算法。它们共用 `steel_schedule_model.py` 中的离散事件仿真和 KPI 计算，差别在于解表示、搜索机制、输出形态和适用时间预算。

| 算法 | 解表示 | 搜索机制 | 输出 | 常见适用场景 | 不建议使用的场景 |
|---|---|---|---|---|---|
| FIFO / 构造规则 | 固定排序 | FIFO、分段优先、短工时、天车感知 | 单个基线解 | 现场应急、接口校验、快速基线 | 需要显著改善多目标或设备负载 |
| SA+Tabu | 钢板排列 | 交换、插入、逆序、同分段扰动、Tabu、降温与回热 | 单目标解或小型 Pareto 档案 | 中等规模、算力有限、希望快速稳定改善 | 需要一次输出完整多目标方案 |
| GA+LNS | 钢板排列 | 锦标赛、OX/PMX 交叉、变异、破坏—修复 | 单目标或双目标档案 | 分段聚集明显、需要种群多样性 | 只允许几十秒级响应 |
| DQN+NSGA-II | 钢板顺序 OS + 机器码 MS | DQN 机器码种子、非支配排序、拥挤度、概率精英 | 四目标 Pareto 前沿 | 同时关心产能、齐套、负载和等待 | 只有一份极端小数据且无法合理训练 DQN |
| DRL-guided SA | 钢板排列 | Q-learning 选择邻域算子和动态权重 | 自适应单目标解 | 数据有限、不同阶段需要不同搜索策略 | 需要完全可解释的固定权重 |
| 稳定右移 | 原排序和原资源 | 只向后平移受故障影响任务 | 快速修复解 | 纯设备故障、减少现场切换 | 取消或插单造成大范围变化 |
| 局部重优化 | 受影响窗口 | 窗口内交换、插入 | 局部改善解 | 订单变更影响约 20% 到 50% 钢板 | 全厂级大范围重排 |
| 全局重优化 | 全部未完成钢板 | SA+Tabu、GA+LNS 或 DQN+NSGA-II | 全局新排程 | 插单、撤单、清台或故障时间较长 | 只要求秒级简单右移 |

算法选择按以下顺序判断：

1. 先判断是否需要 Pareto 多解。如果需要多部门协商或同时保留产能优先和综合交付方案，选择 `DQN+NSGA-II`。
2. 如果只需要一个快速单解，钢板数中等到较大，选择 `SA+Tabu`。
3. 如果同分段钢板较多，GA 的交叉和 LNS 破坏—修复有明显优势，选择 `GA+LNS`。
4. 如果数据量有限，但希望搜索中自动选择邻域和调权重，选择 `DRL-guided SA`。
5. 动态场景先判断受影响比例。小范围故障先用稳定右移或局部重优化，大范围变更再调用全局算法。

推荐主实验配置：

```text
算法：DQN+NSGA-II
种群规模：16
有效代数：10
迭代上限：800
随机种子：20260723
并行：1 进程可复现
```

### 5.4 选择评价函数

评价函数决定算法“认为什么解更好”。项目保留以下函数：

| 评价函数 | 数学形式 | 适合场景 | 主要特点 |
|---|---|---|---|
| 简单目标 | `0.4·Cmax/67.25 + 0.4·Kavg/12.7 + 0.2·ΔL/ΔL_ref` | 快速构造和接口验证 | 权重直观，负载参考值可配置 |
| 产能优先线性 | `J=Cmax/LB+ε·(wK·nK+wL·nL+wW·nW)` | 交期、产量优先 | 先比较 Cmax/LB，再在 1% 产能带内优化辅助指标 |
| 产能优先二次 | `Cmax/LB+ε·(wK·nK²+wL·nL²+wW·nW²)` | 不希望辅助指标恶化 | 对大退步施加更强惩罚 |
| FIFO 相对平衡 | `wC·Cmax/CmaxFIFO+wK·Kavg/KavgFIFO+wL·ΔL/ΔLFIFO` | 计划员日常排程 | 与现有 FIFO 基线直接比较 |
| 二次非线性 | `wC·c²+wK·k²+wL·l²+越界惩罚` | 约束敏感 | 明显超过目标或 FIFO 时惩罚快速上升 |
| 四目标 Pareto | `F=[Cmax/LB,Kavg/KFIFO,ΔL/ΔLFIFO,W/WFIFO]` | 多部门协商 | 不提前固定权重，输出非支配解集 |
| DRL 动态权重 | 平衡、齐套优先、产能优先三组权重动态切换 | 搜索阶段策略变化 | 由 Q-learning 选择权重和邻域算子 |
| 动态规则目标 | `Ccut+0.002·Σ(11-priority)·c+0.05·σload` | 故障、订单变更 | 只优化未完成钢板，兼顾优先级和负载 |

评价函数选择规则：

- 交期最重要：选择“产能优先线性”。
- 齐套是瓶颈：选择“FIFO 相对平衡”或 Pareto 向量中的齐套优先解。
- 不能明显恶化任何指标：选择“二次非线性”。
- 需要给不同部门多套方案：选择“四目标 Pareto”。
- 动态故障和订单变更：选择“动态规则目标”，不要直接用静态目标评价剩余排程。

### 5.5 灵活运行模式

| 能力 | 操作方式 | 实际行为 |
|---|---|---|
| 即时停止 | 点击“停止计算” | 后端设置取消标记，评估器在安全点停止；staging 被丢弃，不写入正式结果和历史记录 |
| 用户指定计算时间 | 设置“最大计算时间” | 实际优化预算为设定时间 × 0.95，并在当前迭代或代结束后停止；内部还有按钢板数缩放的安全上限 |
| 时间优先 | 打开“时间优先模式” | 自动放大迭代次数、种群规模或代数上限，尽量使用完整时间预算 |
| 模型参数优先 | 关闭“时间优先模式” | 忽略最大计算时间，完全按迭代次数、种群规模、代数和代数停机条件运行 |
| 产能优先与三指标综合 | DQN+NSGA-II 一次运行 | 同一 Pareto 前沿上分别输出产能优先解和兼顾产能、齐套、负载的平衡解 |
| 多故障并发 | 添加多条故障记录 | 故障可重叠，支持切割头、胎架、打磨、坡口、AGV 和天车同时受影响 |
| 订单变更并发 | 同时提交取消、优先级和附件更新 | 与故障清单一起进入同一次状态快照和重排 |
| 在制钢板选择 | 选择继续加工或中断清台 | `finish` 保留在制任务，`interrupt` 加入清台时间后释放资源 |
| 剩余模型选择 | stable、SA+Tabu、GA+LNS、DQN+NSGA-II | 小故障用稳定右移，大范围变更用全局模型 |

即时停止和“时间优先”是两套不同机制：停止是用户主动取消；时间优先是用户给算法一个预算，系统自动把搜索规模调到该预算附近。二者不会覆盖已经提交的 `current` 结果。

## 6. 结果解读

### 6.1 指标

分段齐套只针对小件料框；大件不进入 AGV 料框链路，加工完成后进入成品放置区。小件按相同分段和优先级完成齐套后进入小部材放置区。

| 指标 | 含义 | 方向 |
|---|---|---|
| 总完工时间 | 小件齐套与全部大件加工完成的最晚时间 | 越低越好 |
| 加权平均齐套跨度 | 小件组首件到组末件的时间，按小件数加权 | 越低越好 |
| 最大齐套跨度 | 所有小件齐套组中的最大跨度 | 越低越好 |
| 切割负载差 | N2/N5 总切割工时之差 | 越低越均衡 |
| 整体产能 | 钢板数 / 总完工时间 × 8 | 越高越好 |
| 切割机综合稼动率 | 全部切割相关工时 / 可用时间 | 越高越好 |
| 平均设备负载率 | 各加工与物流资源利用率的算术平均 | 越高且分布均衡越好 |
| AGV 路径冲突次数 | 区域互斥造成等待的次数 | 越低越好 |
| 死锁警告数 | 资源循环等待和溢出告警 | 应为 0 |

## 7. 动态响应

### 7.1 故障输入

动态页面支持选择资源：

- 切割头；
- 胎架；
- 配套大件打磨机；
- 配套小件打磨机；
- 分拣桁架臂；
- 自动坡口机；
- 人工坡口工位；
- AGV；
- 天车。

每个故障输入包含：

- 资源 ID；
- 故障开始时间；
- 修复结束时间或修复时长；
- 多个故障可以重叠。

### 7.2 订单变更与紧急插单双模式

附件 2 上传并校验成功后，文件名和钢板数旁边才显示“订单变更”和“紧急插单”。上传未完成或附件 2 不合格时不显示这两个入口。

#### 7.2.1 订单变更模式

选择“订单变更”时：

- 使用原有动态重排算法；
- 新附件 2 作为变更后的订单数据；
- 机器故障、订单时间和在制钢板仍按原逻辑处理；
- 不拆分“新增批次”和“原计划批次”。

支持的订单操作包括取消钢板、调整未投料优先级、重新上传附件 2、增加或删除钢板。已完成钢板不能回滚资源历史；在制钢板可选择继续加工或按清台时间中断。

#### 7.2.2 紧急插单模式

紧急插单把新附件 2 作为新增批次，并保留原计划。执行顺序如下：

1. 读取并校验新增附件 2。
2. 将新增钢板作为前置批次。
3. 使用最大响应时间的约 95% 计算新增批次首 4 张钢板。
4. 立即生成新增批次部分甘特图和 staging CSV。
5. 后台继续完成全部新增附件 2 钢板。
6. 新增批次全部排完后，以其资源释放时间为起点。
7. 计算原计划剩余钢板。
8. 最后统一提交到 `current` 并更新历史记录。

新增批次和原计划若存在同名钢板，系统直接提示重名，不把不同订单错误合并。

## 9. 上报“坡口工作站峰值”的说明

题目材料没有给出坡口工作站、半框缓存和齐套缓存的实际框位数量。模型中的容量是显式参数，不是企业实测值。当前某些场景下坡口工作站峰值超过暂定容量，报告已将其列为风险。

正式投用前必须：

1. 测量坡口工作站、半框缓存和齐套缓存的实际框位；
2. 把容量写入 `ModelConfig`；
3. 对缓存进入执行硬门控；
4. 重新运行静态和动态实验；
5. 重新评估总完工时间、齐套跨度和设备利用率。

## 10. 常见问题

### 10.1 没有 PyTorch

现象：控制台提示 DQN 模型跳过或回退。

处理：安装 `backend/requirements-dqn.txt`，或保持使用启发式机器码。主 NSGA-II 搜索仍然可以执行。

### 10.2 DQN 权重存在但未使用

检查：

- 是否存在 `dqn_machine_model.pt.meta.json`；
- 当前钢板数、板厚、板宽和切割工时是否在元数据范围内；
- PyTorch 是否可导入；
- `dqn_seed_count` 是否大于 0。

### 10.3 计算时间过长

可降低：

- `local_search_iterations`；
- `ga_population_size`；
- `ga_generations`；
- 动态重排时间预算。

不要把种群规模和有效代数降到无法覆盖基本邻域的程度。

### 10.4 前端页面没有更新

前端代码修改后必须重新构建：

```powershell
python .\restart_server.py --skip-deps --skip-tsc
```

### 10.5 中文文件名乱码

系统对上传文件名做了字符集恢复处理。如果仍出现乱码，重命名文件为 ASCII，再重新上传；结果内容和模型计算不受文件名影响。

### 10.6 生成 Word 失败

确认以下 Python 包可用：

```powershell
python -m pip install python-docx Pillow pandas numpy
```

## 12. 结果使用边界

本作品证明的是“在给定数据和显式参数条件下的排产—仿真—重排闭环”。企业正式投产前还要完成以下校准：

- 现场设备数量和能力；
- 实际缓存框位；
- AGV 路径、速度和避让规则；
- 天车空驶和载运时间；
- 故障分布、修复时间和插单频率；
- 坡口、打磨和安全检查口径。

未经校准的默认参数不应作为现场工时承诺。
